# Урок 4: Функции, несколько результатов, defer и ошибки

[English version](../04-functions-errors.md)

## Цель

Научиться проектировать небольшие функции, возвращать несколько значений, представлять сбой значением error, добавлять контекст к ошибкам и гарантировать очистку через defer.

Это базовые инструменты backend-обработчика: обработчик проверяет входные данные, вызывает функцию, проверяет результат и ошибку, а затем возвращает безопасный ответ.

## Объявление функций

Объявление функции состоит из имени, параметров и необязательного типа результата:

```go
func average(total, count int) (float64, error) {
    if count == 0 {
        return 0, ErrDivisionByZero
    }

    return float64(total) / float64(count), nil
}
```

Параметры total и count имеют тип int. Функция возвращает два значения: результат float64 и error. nil означает, что ошибка не произошла.

В обычных ситуациях Go не использует исключения. Функция сообщает о сбое явным возвращаемым значением, а вызывающий код решает, что делать:

```go
result, err := average(15, 2)
if err != nil {
    return
}
fmt.Println(result)
```

Проверяйте ошибку сразу после вызова, который её вернул. Так путь сбоя остаётся видимым, а неправильный результат не используется случайно.

## Несколько возвращаемых значений

Несколько результатов полезны, когда операция может вернуть и значение, и информацию о сбое:

```go
category, err := statusCategory(status)
if err != nil {
    return "", err
}
return category, nil
```

Обычная договорённость — возвращать полезное значение первым, а ошибку вторым. При ошибке возвращайте нулевое значение полезного результата и ненулевую ошибку. При успехе возвращайте результат и nil.

Ошибка — это значение, описывающее сбой. Её нужно проверить, вернуть дальше или осознанно обработать. Не игнорируйте ошибку неиспользуемой переменной только для того, чтобы код скомпилировался.

## Создание и оборачивание ошибок

Используйте errors.New для стабильной ошибки, которую вызывающий код может распознать:

```go
var ErrDivisionByZero = errors.New("division by zero")
```

Используйте fmt.Errorf с глаголом %w, чтобы добавить контекст и сохранить исходную ошибку:

```go
return "", fmt.Errorf("%w: %d", ErrInvalidStatus, status)
```

Теперь сообщение содержит неправильный статус, но вызывающий код по-прежнему может определить категорию через errors.Is:

```go
if errors.Is(err, ErrInvalidStatus) {
    // вернуть ответ о неверных параметрах
}
```

Сравнивайте ошибки по смыслу, а не по тексту. Текст предназначен для человека и может измениться; sentinel-ошибка или типизированная ошибка задают стабильный контракт для кода.

Используйте errors.Is для известной категории, а errors.As — когда нужно получить ошибку конкретного типа. С пользовательскими типами мы подробнее поработаем позже.

## Guard clauses

Проверяйте предусловия в начале функции и сразу возвращайте результат, если условие нарушено:

```go
func inspectStatus(status int, log func(string)) (string, error) {
    if log == nil {
        return "", ErrNilLogger
    }

    log("start")
    defer log("finish")
    return statusCategory(status)
}
```

Nil-логгер отклоняется до вызова. После этой проверки успешный и ошибочный пути используют одно и то же отложенное действие.

## defer

defer планирует вызов функции на момент возврата из окружающей функции:

```go
log("start")
defer log("finish")
```

Вызов finish выполняется при каждом возврате после строки defer, включая возврат из-за ошибки. Поэтому defer удобен для закрытия файлов, снятия блокировки mutex, отката временного состояния или записи конца операции.

Отложенные вызовы выполняются в порядке LIFO — последний добавленный выполняется первым:

```go
defer log("first")
defer log("second")
// при возврате: second, first
```

Аргументы вычисляются в момент выполнения defer, а сам вызов ждёт возврата. Делайте отложенные функции небольшими и не прячьте в них важную ошибку.

В примере используется callback вместо глобального логгера, чтобы порядок событий можно было проверить без глобального состояния. В настоящем backend этот callback может быть заменён структурированным логированием или метриками.

## Разбор примера

Урок объединяет четыре идеи:

1. average возвращает значение и явную ошибку при делении на ноль.
2. statusCategory проверяет HTTP-статус и оборачивает ErrInvalidStatus с неправильным значением.
3. inspectStatus отклоняет nil-зависимость, записывает start и откладывает finish.
4. main проверяет каждую ошибку до использования результата.

Switch без выражения в statusCategory — ещё один способ записать взаимоисключающие условия. Cases проверяются сверху вниз, и возвращается первый совпавший.

## Типичные ошибки

| Ошибка | Почему неверно | Как исправить |
| --- | --- | --- |
| Игнорировать возвращаемую ошибку | Результат может быть неправильным или неполным | Сразу проверять err после вызова |
| Сравнивать ошибки по строке | Текст не является стабильным программным контрактом | Использовать errors.Is или errors.As |
| Возвращать полезное значение вместе с ненулевой ошибкой без договора | Вызывающий код может случайно использовать это значение | При ошибке возвращать нулевой результат, если частичные данные явно не разрешены |
| Вызывать зависимость до её проверки | Nil-функция или объект могут вызвать panic | Сначала проверять предусловия |
| Ожидать defer при аварийном завершении процесса | defer выполняется при возврате из функции, а не при резком завершении процесса | Использовать его для обычной очистки функций, а не для восстановления после падения |
| Делать defer внутри огромного цикла | Очистка ждёт возврата внешней функции, и ресурсы накапливаются | Вынести одну итерацию в отдельную функцию |

## Практика

1. Добавьте parsePort(text string) (int, error). Принимайте десятичные порты от 1 до 65535 и возвращайте осмысленную ошибку для остальных значений. Используйте strconv.Atoi и добавляйте контекст к ошибкам валидации.
2. Добавьте safeAverage(values []int) (float64, error). Для nil- или пустого входа возвращайте ErrEmptyInput и избегайте целочисленного деления.
3. Добавьте classifyError(err error) string. Возвращайте стабильные категории для ErrDivisionByZero, ErrInvalidStatus и неизвестной ошибки через errors.Is.
4. Добавьте withEvents(action func() error, log func(string)) error. Записывайте start и finish через defer и сохраняйте ошибку action.
5. Расширьте тесты так, чтобы отложенный finish записывался, когда action возвращает ошибку.

Для каждой функции сначала определите контракт ошибок. Проверьте успешный путь, граничные значения и каждый описанный сбой. Не сравнивайте тексты ошибок, если контракт описывает категорию ошибки.
