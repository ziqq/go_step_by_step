# 47. Ограничиваем размер кадра до выделения памяти

[English version](../47-bounded-frames.md) · [Запускаемый пример](../../lessons/47-bounded-frames/main.go)

Урок 46 ограничивает время чтения при молчании клиента. Активный клиент может объявить огромный размер данных. Проверь заявленную длину до выделения памяти. В бэкенде чата лимит чтения WebSocket задаётся до обработки входящих кадров.

Пример использует простой формат с длиной в четырёх беззнаковых байтах big-endian перед данными. Лимит задаётся доверенной серверной конфигурацией. Владелец соединения сочетает чтение с дедлайном и закрывает сессию при ошибке формата. Формат кадров WebSocket и его лимит обрабатывает библиотека.

## Проследи за проверкой

1. Проверь положительный лимит до чтения. Получи заголовок через io.ReadFull, поскольку сетевой Read может вернуть меньше запрошенного числа байтов.

2. Декодируй беззнаковую длину и сравни её с лимитом через uint64. Преобразуй её в int после сравнения. Размер данных поместится в положительный лимит типа int на текущей архитектуре.

3. Размер ровно на границе допустим. Превышение возвращает errFrameTooLarge до выделения памяти и чтения данных. После ошибки владелец закрывает сессию, поскольку данные кадра остались в потоке.

4. Нулевая длина задаёт допустимый пустой кадр. EOF до первого байта заголовка означает завершение между кадрами. Неполный заголовок или данные означают обрезанный кадр. Сохрани причину ошибки для проверки через errors.Is.

## Практика · Ограничь суммарные данные сессии

Добавь чтение сессии с положительным лимитом одного кадра и положительным общим бюджетом данных. Передавай полные кадры в callback, который возвращает error.

1. Повторно используй логику заголовка и чтения данных. До выделения памяти и чтения данных отклоняй размер, превышающий лимит кадра или остаток бюджета. Для исчерпания бюджета сессии введи отдельную ошибку. Байты заголовков не входят в бюджет.

2. Учитывай данные после полного чтения кадра, до вызова callback. При ошибке callback остановись и сохрани причину. Кадр, который точно расходует остаток, допустим. Продолжай читать заголовки, чтобы EOF завершал поток, а пустые кадры оставались допустимыми. Следующий кадр положительного размера превысит бюджет.

3. Проверь несколько допустимых по отдельности кадров с превышением общей суммы, точное расходование с последующим EOF, пустой кадр после точного расходования, отказ до чтения лишних данных, оба недопустимых лимита, обрезанный ввод и ошибку callback без чтения следующего заголовка. Объясни, зачем сочетать ограничения байтов с дедлайнами и ограничением частоты кадров при допустимых пустых кадрах.

## Типичные ошибки

- Выделение памяти до проверки длины позволяет клиенту управлять её расходом.

- Любой EOF, принятый за обычное отключение, скрывает обрезанный кадр.

- Продолжение после слишком большого заголовка принимает данные за длину следующего кадра.

- Лимит одного кадра позволяет долгой сессии обработать неограниченную сумму данных.

## Критерии завершения

Пример выводит ожидаемую строку, исходные тесты проходят с детектором гонок. Новые тесты проверяют оба бюджета, сохраняют причины ошибок и подтверждают, что лишние данные остались непрочитанными. Объясни дополнительную защиту от потока пустых кадров.
