# 50. Согласование подпротокола сессии

[English version](../50-session-subprotocol.md) · [Запускаемый пример](../../lessons/50-session-subprotocol/main.go)

Урок 49 проверял Origin браузера. Перед обработкой JSON-команд из урока 48 стороны должны согласовать прикладной протокол. Пример требует условный токен `chat.v1`. Он отделён от версии WebSocket 13, аутентификации и доступа к беседе. В референсном backend есть upgrader и конверты команд; этот урок исследует дополнительную политику согласования версий и не утверждает, что референс уже использует такой токен.

## Запустите и проследите

```sh
go run ./lessons/50-session-subprotocol
go test -count=1 -v ./lessons/50-session-subprotocol
go test -race ./lessons/50-session-subprotocol
go vet ./lessons/50-session-subprotocol
```

```text
chat.v1
subprotocol rejected
subprotocol rejected
```

Программа запускает чистую функцию выбора. Она не открывает сокет и не выполняет HTTP upgrade.

## Как выполняется выбор

1. Передайте все значения из `r.Header.Values("Sec-WebSocket-Protocol")`. Предложения запроса могут занимать несколько строк заголовка и содержать списки через запятую. Разделите каждую строку, удалите только внешние ASCII-пробелы и табуляции и проверьте каждый токен. Токен содержит непустую последовательность ASCII-букв, цифр или знаков из `validToken`; кавычки, слеши, управляющие и не-ASCII байты запрещены.

2. Учитывайте точные токены в локальной карте. Дубликаты внутри строки и между строками отклоняются. Значения чувствительны к регистру. Имена заголовков регистронезависимы, но это не делает `Chat.v1` равным `chat.v1`. Парсер намеренно отклоняет пустые элементы списка, а не пропускает их.

3. Завершите всю проверку перед выбором `chat.v1`. Ошибочный токен в конце отклоняет весь запрос, даже если совпадение уже найдено. Корректные неподдерживаемые токены могут соседствовать с поддерживаемым. Отсутствие предложений или совпадения приводит к ошибке: этот endpoint требует подпротокол на уровне приложения.

4. В реальном endpoint отклоните ошибку до upgrade и настройте upgrader так, чтобы при успехе он вернул ровно один выбранный предложенный токен. Сохраните проверки аутентификации, Origin и membership. Остальную проверку handshake и ответ 101 оставьте библиотеке. Не отражайте весь клиентский заголовок и не собирайте upgrade вручную в этом примере. Ограничение размера HTTP-заголовков задаётся на границе сервера.

RFC 6455 описывает предложения запроса, выбор из этих предложений и различие числа заголовков в запросе и ответе. Общий протокол допускает отсутствие выбранного подпротокола; обязательность здесь является явной политикой приложения. См. [RFC 6455, разделы 4.1, 4.2.2 и 11.3.4](https://www.rfc-editor.org/rfc/rfc6455).

## Практика · Проверьте выбор сервера

Добавьте клиентскую функцию `validateSelection(offered []string, response []string) error`. `offered` содержит отдельные имена токенов из собственного предложения клиента; `response` содержит все значения заголовка ответа. Не реализуйте WebSocket-клиент и не меняйте серверный выбор.

1. Проверьте весь срез `offered`: нужен непустой список уникальных корректных токенов без внешних пробелов. Принимайте ответ только с одним значением заголовка, которое после удаления внешних ASCII-пробелов и табуляций является одним корректным токеном из `offered` с точным регистром. Ответ — один выбор, а не список предложений через запятую. При любом отклонении возвращайте `errProtocol`, при успехе nil. Приложение требует выбор, хотя общий протокол WebSocket допускает его отсутствие.

2. Проверьте предложенный выбор, корректный выбранный токен в начале и конце списка предложений, внешние пробелы/табуляции ответа, отсутствие ответа, пустой ответ, несколько строк, включая одинаковые, список через запятую, непредложенный токен, неверный регистр, ошибочный токен и ошибочные/повторные/пустые предложения. Убедитесь, что оба входных среза неизменны. Сохраните исходные тесты.

3. Выполните целевые и общие проверки. Объясните, почему совместимая форма JSON не оправдывает непредложенный выбор, почему клиент должен отклонить его до приёма прикладных сообщений и какие части полного handshake остаются ответственностью WebSocket-библиотеки.

```sh
gofmt -w lessons/50-session-subprotocol/main.go lessons/50-session-subprotocol/main_test.go
go test ./...
go test -race ./...
go vet ./...
```

## Типичные ошибки

- Возврат при первом совпадении пропускает ошибочный хвост.

- Header.Get теряет следующие сохранённые значения заголовка.

- Приведение значений токенов к нижнему регистру незаметно меняет контракт.

- Возврат всех предложений создаёт список в ответе вместо одного выбора.

- Смешение `chat.v1` с версией транспорта 13 или с проверенной identity.

## Критерии завершения

Проследите три результата примера. Выполните задание проверки клиентского выбора с положительными и отрицательными тестами, сохранив серверный контракт. Объясните различие списка запроса и одного выбора ответа, обязательность выбора в приложении и границу совместимости протокола и авторизации.
