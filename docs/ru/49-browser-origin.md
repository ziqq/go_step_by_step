# 49. Проверяем Origin браузера до WebSocket upgrade

[English version](../49-browser-origin.md) · [Запускаемый пример](../../lessons/49-browser-origin/main.go)

Перед чтением сессии из уроков 47–48 HTTP-рукопожатие браузера проходит проверку Origin. В бэкенде чата upgrader содержит callback CheckOrigin. Пример показывает endpoint только для браузера с двумя фиксированными доверенными источниками.

## Запусти и проследи

```sh
go run ./lessons/49-browser-origin
go test -count=1 -v ./lessons/49-browser-origin
go test -race ./lessons/49-browser-origin
go vet ./lessons/49-browser-origin
```

```text
204
403
```

Обработчик с ответом 204 обозначает границу upgrade. Пример вызывает HTTP-обработчик через httptest. В приложении поставь эту проверку перед настоящим upgrader.

## Проследи за проверкой

1. Получи Header.Values("Origin") и потребуй ровно одно значение. Отклоняй отсутствующий и пустой заголовок, null, повторные строки и списки. Этот endpoint принимает запросы браузера с одним доверенным источником.

2. Сравни полное значение с фиксированным списком. Схема и порт имеют значение. Суффикс chat.example.test.attacker.test отклоняется. Точное сравнение также отклоняет user info, путь, query и явное :443, которого нет в списке.

3. Отклоняй запрос до вызова следующего обработчика. Тесты проверяют ноль вызовов при отказе, один при допуске и стабильное тело 403 без данных запроса. Host и заголовки прокси не расширяют список доверия.

4. Продолжай аутентификацию и проверку доступа к беседе после этой проверки. Произвольный клиент может задать Origin. Референсный бэкенд отдельно поддерживает нативных клиентов без Origin. Для этого нужна явно спроектированная политика клиентов вместе с аутентификацией. В этом уроке контракт браузерного endpoint отклоняет отсутствующий Origin.

Origin описывает источник инициатора. Header.Values возвращает сохранённые значения, позволяя проверить их количество. Пример сравнивает точные сериализованные строки без нормализации. [RFC 6454](https://www.rfc-editor.org/rfc/rfc6454), [Go Header.Values](https://pkg.go.dev/net/http#Header.Values)

## Практика · Подготовь список Origin из конфигурации

Замени два литерала конструктором, который принимает []string и возвращает проверку или ошибку. Проверяй весь список при запуске до публикации готового обработчика.

1. Потребуй хотя бы одну запись. Формат конфигурации в задании — https://, затем DNS-имя в нижнем регистре ASCII и необязательный нестандартный десятичный порт от 1 до 65535. Метки DNS содержат буквы, цифры или внутренние дефисы, без пустых меток и точки в конце. Потребуй минимум две метки. Отклоняй пробельные символы, wildcard, null, user info, путь включая /, query включая пустой ?, fragment, IP-адреса, верхний регистр, :443 и ведущие нули порта. Разбери URL и явно проверь остальные части.

2. Отклоняй повторы и весь конструктор при любой ошибочной записи. Скопируй допустимые значения в собственное закрытое состояние, чтобы изменение исходного среза не меняло допуск. Сохрани точное сравнение запросов и исходные правила отказа. Пустая конфигурация должна возвращать ошибку.

3. Добавь тесты допустимого стандартного и нестандартного порта, каждой категории отказа, повторов, смешанного списка и изменения исходного среза. Проверь параллельные запросы к готовому обработчику с детектором гонок. При отказе следующий обработчик вызываться не должен. Объясни, зачем готовить конфигурацию один раз при запуске вместо чтения переменной окружения на каждый запрос.

```sh
gofmt -w lessons/49-browser-origin/main.go lessons/49-browser-origin/main_test.go
go test ./...
go test -race ./...
go vet ./...
```

## Типичные ошибки

- Сравнение префикса или суффикса допускает чужие домены.

- Header.Get скрывает дополнительные сохранённые значения от проверки количества.

- Wildcard или допуск при пустом списке незаметно расширяет доступ.

- Origin, принятый за principal, пропускает аутентификацию.

- Проверка после upgrade выполняется слишком поздно для HTTP 403.

## Критерии завершения

Проследи пути 204 и 403. Выполни практику конфигурации с сохранением исходных тестов. Покажи атомарный отказ при неверной конфигурации, независимость от исходного среза и прохождение параллельных запросов с детектором гонок. Объясни отличие проверки источника браузера от аутентификации пользователя.
