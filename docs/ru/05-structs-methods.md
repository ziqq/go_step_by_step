# Урок 5: структуры, методы, указатели и композиция

## Цель

После урока вы должны уметь:

- объединять связанные данные в `struct`;
- выбирать value receiver или pointer receiver для метода;
- использовать нулевое значение и безопасно работать с указателем;
- собирать типы композицией и embedding;
- тестировать небольшую предметную модель.

Это первый шаг к backend-моделям: сообщению чата, событию или пользователю. Структура описывает данные, а методы держат поведение рядом с данными, которые они читают или изменяют.

## 1. Структуры объединяют связанные значения

Структура — это именованный набор полей. Именованный литерал обычно понятнее: каждое значение находится рядом с именем своего поля:

```go
type Message struct {
	ID      int
	Author  string
	Content string
}

message := Message{
	ID:      1,
	Author:  "Anton",
	Content: "Hello",
}
```

Неуказанные поля получают нулевые значения. Поэтому `Message{}` корректен: он создаёт пустое сообщение с `ID == 0` и пустыми строками.

Для собственных структур предпочитайте именованные литералы. Литерал без имён зависит от порядка полей и легко ломается после добавления нового поля:

```go
message := Message{1, "Anton", "Hello"}
```

## 2. Методы описывают поведение

Метод — это функция с receiver. У `Summary` value receiver: метод читает копию значения `Message` и не меняет оригинал:

```go
func (m Message) Summary() string {
	return fmt.Sprintf("%s: %s", m.Author, m.Content)
}
```

Вызывайте метод привычным синтаксисом через точку:

```go
summary := message.Summary()
```

Используйте value receiver, когда метод только читает значение, значение небольшое и его копирование приемлемо. Такой receiver работает и для адресуемого значения, и для указателя на это значение.

## 3. Pointer receiver изменяет исходное значение

`AddMessage` изменяет срез `Messages` внутри `Chat`, поэтому у метода pointer receiver:

```go
func (c *Chat) AddMessage(message Message) {
	c.Messages = append(c.Messages, message)
}

chat := Chat{Name: "support"}
chat.AddMessage(message)
```

Для этого вызова компилятор автоматически берёт адрес адресуемого значения `chat`. Указатель можно написать явно:

```go
chat := &Chat{Name: "support"}
chat.AddMessage(message)
```

Важен тип receiver:

```go
func (c Chat) ResetName() {
	c.Name = ""
}
```

Здесь меняется только копия, поэтому имя исходного чата не сбросится. Для изменения значения вызывающему коду нужен `*Chat`:

```go
func (c *Chat) ResetName() {
	c.Name = ""
}
```

## 4. Указатели и nil

Указатель хранит адрес значения. Оператор `&` берёт адрес, а `*` разыменовывает указатель:

```go
message := Message{ID: 1}
pointer := &message
pointer.ID = 2

fmt.Println(message.ID) // 2
```

Нулевое значение указателя — `nil`. Вызов метода через nil-указатель может привести к panic, если метод разыменует receiver. Если указатель может быть `nil`, проверяйте его до использования.

Нулевое значение структуры часто уже полезно и не требует конструктора. Это важная привычка Go: по возможности делать обычное нулевое значение безопасным и осмысленным.

## 5. Метод может вернуть значение и признак успеха

У пустого чата нет последнего сообщения. `LastMessage` возвращает нулевое `Message` и `false`:

```go
func (c Chat) LastMessage() (Message, bool) {
	if len(c.Messages) == 0 {
		return Message{}, false
	}

	return c.Messages[len(c.Messages)-1], true
}
```

Вызывающий код обязан проверить флаг до использования результата:

```go
last, ok := chat.LastMessage()
if !ok {
	return
}

fmt.Println(last.Summary())
```

Пара `(value, bool)` удобна, когда отсутствие — нормальная ситуация. Позже, когда понадобится объяснять причину сбоя, мы будем использовать `(value, error)`.

## 6. Композиция и embedding

В Go нет наследования классов. Большой тип можно собрать из маленьких. При embedding поля и методы встроенного типа становятся доступны через внешний тип:

```go
type Identified struct {
	ID int
}

type Event struct {
	Identified
	Kind string
}

event := Event{
	Identified: Identified{ID: 42},
	Kind:       "message.created",
}

fmt.Println(event.ID)
```

`event.ID` — сокращение для `event.Identified.ID`. Явная форма тоже корректна и бывает понятнее, когда несколько встроенных типов предоставляют поля с одинаковыми именами. Embedding — это композиция, а не наследование: `Event` содержит значение `Identified` и просто предоставляет удобный доступ к его полям.

## 7. Прочитайте пример вместе с тестами

У примера три ответственности:

- `Message` хранит данные сообщения и формирует краткое описание;
- `Chat` хранит список и предоставляет методы чтения и изменения;
- `Event` объединяет переиспользуемый идентификатор с типом события.

Тесты проверяют поведение, а не внутреннюю реализацию. В частности, `TestChatAddMessageMutatesReceiver` упадёт, если случайно заменить pointer receiver на value receiver, а табличный тест `LastMessage` покрывает пустой и заполненный чат.

## Частые ошибки

- Использовать литерал структуры без имён для собственного типа, а затем сломать вызовы добавлением поля.
- Выбрать value receiver для метода, который должен менять значение вызывающего кода.
- Забыть, что указатель может быть `nil`.
- Воспринимать embedding как наследование и ожидать поведение подкласса.
- Использовать результат `LastMessage`, не проверив возвращённый `bool`.
- Автоматически добавлять конструктор, хотя нулевое значение структуры уже работает.
