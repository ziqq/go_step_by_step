# 42. Рассылка временных событий чата с ограниченными очередями

[English version](../42-ephemeral-fanout.md) · [Запускаемый пример](../../lessons/42-ephemeral-fanout/main.go)

У одного события чата может быть несколько подписчиков, в том числе разные устройства. Каждому нужна своя очередь. В сервере чата рассыльщик пытается доставить временное событие каждой выбранной сессии и может пропустить медленного получателя. В примере используем ключ беседы и строку события. Считаем, что вызывающий уже проверил право подписчика на доступ к беседе.

## Запуск примера

```sh
go run ./lessons/42-ephemeral-fanout
go test -count=1 -v ./lessons/42-ephemeral-fanout
go test -race -count=20 ./lessons/42-ephemeral-fanout
go vet ./lessons/42-ephemeral-fanout
```

```text
fast: typing started
fast: typing stopped
slow: typing started
```

Обе очереди вмещают по одному событию. Быстрый подписчик читает первое событие до второй публикации. В очереди медленного подписчика первое событие ещё занимает место, поэтому второе пропускается. Попробуй прочитать медленную очередь между двумя публикациями и увидеть, как ей приходят оба события.

## Как проходит публикация

1. Рассыльщик создаёт отдельный буферизованный канал для каждой подписки. Вызывающий получает канал только для чтения и функцию отписки. Он отвечает за срок жизни подписки и вызывает отписку при завершении сессии.

2. Рассыльщик делает одну попытку отправки каждому текущему подписчику выбранной беседы. Ветка `default` позволяет сразу пропустить заполненную очередь. События в очереди сохраняют порядок, а остальные подписчики получают свою попытку доставки. Так ограничивается очередь каждой подписки. Для ограничения числа сессий можно применить лимит из урока 41.

3. Публикация и отписка используют один мьютекс. Отписка удаляет конкретную очередь и закрывает её под тем же мьютексом. Поэтому отправка и закрытие не пересекаются, а повторная отписка безопасна. Уже помещённые в очередь события доступны для чтения после закрытия канала.

4. Мьютекс защищает короткий обход с неблокирующими отправками. Запись в сокет выполняет потребитель сессии. Пропуск подходит для подсказок со сроком жизни, например состояния набора текста. Для сохранённых сообщений нужен контракт доставки и восстановления, например повторное чтение из истории.

## Практика · Верни результат одной публикации

Добавь результат `Delivery` с целочисленными полями `Enqueued` и `Dropped` и возвращай его из `publish`. Сохрани правила очереди, области рассылки и отписки.

1. Считай одну доставку в очередь за успешную отправку и один пропуск за заполненную очередь. Сумма равна числу подписчиков, которых обошёл вызов. Успешная отправка подтверждает передачу события в канал. Для пустой или неизвестной беседы верни два нуля.

2. Проверь публикацию с заполненной очередью одного подписчика и свободной очередью другого. Затем освободи место и опубликуй снова. Проверь оба счётчика и полученные события после каждого вызова. Проверь нулевые значения после последней отписки. Подписки на другие беседы не должны учитываться.

3. Проверь гонку публикации с отпиской. Используй общий канал старта и дождись завершения горутин. При одной изначально пустой очереди результат должен содержать одну доставку, если публикация успела первой, или ноль попыток, если первой была отписка. Проверь, что чтение закрытой очереди согласуется с результатом. Объясни, почему счётчики описывают этот вызов, даже если подписчик сразу после него вышел.

## Типичные ошибки

- Общий канал для нескольких потребителей распределяет события между ними. Для рассылки нужна отдельная очередь на подписку.
- Выход при первой заполненной очереди пропускает некоторых других подписчиков.
- Копирование списка каналов с последующей отправкой после снятия мьютекса может привести к отправке в уже закрытый канал.
- Успешная отправка в локальный канал не подтверждает получение по сети.

## Критерии завершения

Пример печатает три строки в указанном порядке. Существующие и добавленные тесты проходят с детектором гонок. Счётчики описывают один вызов и согласуются с доступными событиями, в том числе при полной очереди и отписке.
