# 46. Продлеваем дедлайн чтения сессии по pong

[English version](../46-session-read-deadline.md) · [Запускаемый пример](../../lessons/46-session-read-deadline/main.go)

В уроке 45 одна горутина отправляет ping. В бэкенде чата чтение начинается с установленным дедлайном, а обработчик pong его продлевает. Если клиент перестаёт отвечать, заблокированное чтение завершается по таймауту. В примере соединение работает в памяти, а кадры состоят из одного байта. P обозначает pong, D обозначает прикладные данные.

## Проследи за чтением

1. Установи первый дедлайн до цикла. Если клиент молчит, чтение без дедлайна может удерживать горутину бесконечно.
2. При pong установи дедлайн на текущее время плюс допустимый период молчания. Обычные данные оставляют дедлайн прежним, поэтому трафик не подменяет подтверждение heartbeat.
3. Останови цикл при ошибке установки дедлайна. Таймаут соединения после обёртки по-прежнему распознаётся через errors.Is и os.ErrDeadlineExceeded.
4. Цикл владеет чтением. При остановке владелец сессии может закрыть соединение и разблокировать чтение. Дедлайн ограничивает ввод-вывод. Блокирующим прикладным обработчикам нужен собственный лимит времени.

## Практика · Ограничь время жизни сессии

Добавь в readSession положительный параметр maxLifetime. Предельный момент равен времени начала сессии плюс maxLifetime.

1. Установи начальный дедлайн на более ранний из двух моментов: дедлайн heartbeat или конец сессии. Каждый новый дедлайн при pong ограничивай тем же предельным моментом.
2. Отклоняй нулевой или отрицательный maxLifetime до обращения к соединению. Если при обработке pong время достигло предела или прошло его, верни ошибку, распознаваемую как os.ErrDeadlineExceeded, и оставь дедлайн прежним.
3. С управляемыми часами и записью вызовов SetReadDeadline проверь начальное ограничение, продление до предела и pong ровно в предельный момент. Проверь оба недопустимых значения и сохрани тест с молчащим соединением.

## Типичные ошибки

- Продление после каждого чтения позволяет обычному трафику скрывать пропущенные ответы heartbeat.
- Прибавление maxLifetime ко времени каждого pong сдвигает конец сессии бесконечно.
- Обработка таймаута как обычного EOF скрывает причину завершения.
- Долгий прикладной обработчик задерживает следующее чтение даже при установленном дедлайне соединения.

## Критерии завершения

Пример выводит обе строки. Тесты проходят с детектором гонок. Ни один дедлайн не выходит за предел сессии, недопустимые значения не приводят к вводу-выводу, а pong ровно в предельный момент заканчивается таймаутом.
