# Урок 3: Массивы, срезы, карты и range

[English version](../03-collections.md)

## Цель

Научиться хранить группы значений в Go, перебирать их через range, расширять срезы с помощью append и считать или искать значения в картах.

Коллекции встречаются в каждом backend: страница сообщений — это срез, набор поддерживаемых методов можно представить картой, а ответ часто содержит список записей.

## Перед началом

Запускайте команды из корня репозитория:

    go run ./lessons/03-collections
    go test ./lessons/03-collections

Ожидаемый вывод:

    status count: 5
    status sum: 1829
    unique methods: [messages.send messages.load]
    status frequencies: map[200:1 201:1 429:2 500:1]

Порядок элементов карты не гарантирован. Показанный вывод — только один из возможных вариантов.

## Массивы

У массива фиксированная длина, которая является частью его типа:

    var limits [3]int
    values := [3]int{10, 20, 30}

Типы [3]int и [4]int — разные типы. Массивы являются значениями: присваивание массива копирует все его элементы. Используйте массив, когда размер действительно фиксирован и является частью предметной области.

В прикладном коде чаще используются срезы. Срез — это небольшой дескриптор, указывающий на внутренний массив, с длиной и ёмкостью.

## Срезы

Создать срез можно литералом:

    statuses := []int{200, 404, 500}

Длина — количество элементов. Ёмкость — сколько элементов помещается во внутреннем массиве до того, как Go выделит новый:

    len(statuses)
    cap(statuses)

Для чтения и изменения элемента используется индекс:

    statuses[0] = 201
    first := statuses[0]

Индексы начинаются с нуля. Чтение за пределами диапазона вызывает panic, поэтому индексы из внешнего запроса нужно проверять.

У nil-среза длина и ёмкость равны нулю, и его безопасно перебирать:

    var values []int
    fmt.Println(len(values)) // 0

append возвращает итоговый срез. Всегда присваивайте результат, потому что append может выделить новый внутренний массив:

    values = append(values, 10)
    values = append(values, 20, 30)

Разница между nil-срезом и пустым срезом может быть важна при JSON-кодировании. Nil-срез обычно превращается в null, а ненулевой пустой срез — в []. Выбирайте представление, которое требует контракт API.

## range

Форма range перебирает коллекцию:

    for index, status := range statuses {
        fmt.Println(index, status)
    }

Для среза или массива range возвращает индекс и копию элемента. Если индекс не нужен, используйте blank identifier:

    for _, status := range statuses {
        if status >= 500 {
            // обработать ошибку сервера
        }
    }

Значение является копией. Изменение status внутри цикла не изменит срез. Для изменения элементов используйте индекс:

    for index := range statuses {
        statuses[index]++
    }

Этим же синтаксисом можно перебирать карту, но порядок элементов карты намеренно не определён:

    for method, count := range methodCounts {
        fmt.Println(method, count)
    }

Никогда не делайте порядок ответа API или теста зависимым от порядка карты. Если нужен детерминированный вывод, сортируйте ключи; сортировку мы позже разберём со стандартной библиотекой.

## Карты

Карта хранит пары ключ-значение:

    counts := make(map[int]int)
    counts[200]++
    counts[500] = 2

Нулевое значение карты — nil. Чтение отсутствующего ключа из nil-карты безопасно и возвращает нулевое значение типа, но запись в nil-карту вызывает panic. Перед записью инициализируйте карту через make или литерал.

Используйте форму comma-ok, чтобы отличить отсутствующий ключ от сохранённого нулевого значения:

    count, exists := counts[404]
    if !exists {
        count = 0
    }

Функция delete удаляет ключ. Удаление отсутствующего ключа безопасно:

    delete(counts, 404)

Карта в countStatuses использует полезное свойство нулевого значения. При первой встрече со статусом counts[status] сначала равно нулю, поэтому увеличение сразу создаёт значение один.

## Множества через map

В Go нет встроенного типа set. Частое представление — карта со значениями пустого struct:

    seen := make(map[string]struct{})
    seen["messages.send"] = struct{}{}

Пустой struct не занимает места для значения. Карта в uniqueMethods запоминает уже добавленные методы, а срез сохраняет порядок их первого появления.

Не используйте одну карту как set, если одновременно нужен стабильный порядок вывода. Держите срез для порядка и карту для быстрых проверок принадлежности, как в примере.

## Разбор примера

Пример моделирует небольшую пачку backend-наблюдений:

1. statuses — срез, потому что размер каждой пачки меняется.
2. sum использует range для обработки каждого статуса.
3. uniqueMethods объединяет карту для проверки принадлежности и срез для стабильного порядка.
4. countStatuses агрегирует количество появлений по коду статуса в карте.

Такая форма используется, когда backend обрабатывает страницу записей, группирует события по ключу или удаляет дубликаты методов команд.

## Как читать тесты

Тесты покрывают nil- и пустые срезы, отрицательные значения, дубликаты, порядок первого появления и подсчёт в карте. reflect.DeepEqual используется только для сравнения коллекций в тестах и не меняет работу production-функций.

Запустите тесты подробно:

    go test -v ./lessons/03-collections

Перед коммитом запускайте все проверки репозитория:

    go fmt ./...
    go test ./...
    go test -race ./...
    go vet ./...

## Типичные ошибки

| Ошибка | Почему неверно | Как исправить |
| --- | --- | --- |
| Считать массив и срез одним и тем же | У них разные типы, правила копирования и ограничения длины | Использовать массив для фиксированного размера, срез — для изменяемой коллекции |
| Игнорировать результат append | append может вернуть срез с новым внутренним массивом | Присвоить результат обратно срезу |
| Записывать в nil-карту | Nil-карту можно читать, но нельзя изменять записью | Инициализировать её через make или литерал |
| Предполагать порядок карты | Порядок range по карте не определён | Сортировать ключи или сохранять порядок в отдельном срезе |
| Изменять значение range | Переменная значения — копия элемента | Для изменения исходного среза использовать индекс |
| Случайно отдавать внутреннее хранилище | Вызывающий код сможет изменить срез, который должен быть приватным | При границе владения делать копию, если это необходимо |

## Практика

1. Добавьте contains(values []string, wanted string) bool. Возвращайте true, если wanted встречается в срезе. Проверьте nil, пустой срез, первый, средний и отсутствующий элемент.
2. Добавьте filterStatuses(statuses []int, minimum int) []int. Возвращайте новый срез со статусами не меньше minimum. Не изменяйте входной срез.
3. Добавьте mergeCounts(left, right map[string]int) map[string]int. Складывайте значения с одинаковыми ключами и оставляйте обе входные карты без изменений.
4. Добавьте average(values []int) float64. Для nil- или пустого входа возвращайте 0 и избегайте целочисленного деления.
5. Добавьте sortedStatusCodes(counts map[int]int) []int как предварительное упражнение для детерминированного вывода карты. Можно использовать sort.Ints из стандартной библиотеки.

Для каждой новой функции сначала напишите тесты, затем меняйте main. Добавляйте nil- или пустые коллекции, дубликаты и граничные случаи, если их допускает контракт.
