# 44. Сигналы и периодическое чтение сохранённых событий

[English version](../44-event-wake.md) · [Запускаемый пример](../../lessons/44-event-wake/main.go)

Урок 43 читает сохранённые события после курсора. Подключённой сессии также нужно решать, когда читать снова. Сервер чата подписывается на сигнал перед загрузкой событий, а затем ждёт нового сигнала, тика таймера или отмены. Сигнал сообщает о возможном появлении данных. Сами события и их порядок определяет хранилище.

## Запуск примера

```sh
go run ./lessons/44-event-wake
go test -count=1 -v ./lessons/44-event-wake
go test -race ./lessons/44-event-wake
go vet ./lessons/44-event-wake
```

```text
initial read applied event 1
wake read applied event 2
periodic read applied event 3
```

Пример сам отправляет оба сигнала по очереди, чтобы вывод был воспроизводимым. Сервис может передать канал тикера и остановить тикер при завершении сессии.

## Как работает цикл

1. Подпишись перед первым чтением. Событие может зафиксироваться в хранилище во время чтения. Буфер позволяет сохранить сигнал до момента, когда цикл начнёт ждать.
2. Сразу прочитай события, затем повторяй чтение после сигнала или тика. Функция обновления хранит последний принятый курсор и выполняется последовательно. Несколько уведомлений могут соответствовать одному чтению. Тик запускает чтение, даже если уведомление потерялось.
3. Закрытый канал всегда готов к чтению. После обнаружения закрытия присвой nil локальной переменной канала. Если оба входа закрыты, цикл ждёт отмены контекста.
4. При ошибке чтения останови цикл и сохрани причину ошибки. Проверяй отмену перед каждым чтением и передавай контекст функции обновления, чтобы она могла прервать блокирующий ввод-вывод.

## Практика · Объедини ожидающие сигналы

Добавь неблокирующую функцию отправки сигнала в канал ёмкостью один. Вызывающий владеет каналом и держит его открытым, пока работают отправители.

1. Вызывай функцию после успешной фиксации события. Один ожидающий сигнал уже означает, что нужно обновить данные. Повторные вызовы при полном канале должны быстро завершаться и оставлять в очереди ровно один сигнал.
2. Проверь повторные и конкурентные вызовы без читателя. Прочитай один накопленный сигнал и проверь, что следующий вызов снова помещает сигнал в канал. Используй таймаут, чтобы обнаружить блокировку, и дождись завершения тестовых горутин.
3. В примере замени прямую отправку вызовами функции. Сохрани периодическое чтение и объясни, как оно помогает при пропуске уведомления. Объясни, почему один общий канал для нескольких сессий будит только одного получателя на сигнал.

## Типичные ошибки

- Ожидание перед первым чтением задерживает уже сохранённые события до сигнала или тика.
- Отправка сигнала до коммита может разбудить читателя до появления события в хранилище.
- Чтение закрытого канала как нового сигнала запускает непрерывный цикл.
- Неограниченная очередь сигналов накапливает повторные уведомления во время медленного чтения.

## Критерии завершения

Пример выводит три чтения по порядку. Исходные и добавленные тесты проходят с детектором гонок. Серия вызовов оставляет один ожидающий сигнал, после чтения можно отправить новый, а периодическая проверка продолжает работать.
