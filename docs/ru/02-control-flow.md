# Урок 2: Операторы и управление выполнением

[English version](../02-control-flow.md)

## Цель

Научиться объединять значения операторами, принимать решения с помощью if, повторять действия через for, делать ранний return и понимать область видимости переменных.

В примерах используются HTTP-коды ответа, потому что backend постоянно решает, успешен ли ответ, нужно ли повторить операцию или её следует остановить.

## Перед началом

Запускайте команды из корня репозитория:

```sh
go run ./lessons/02-control-flow
go test ./lessons/02-control-flow
```

Ожидаемый вывод:

```text
status 503: retry
retry delay for attempt 3: 4s
sum of first 5 numbers: 15
```

## Операторы

Арифметические операторы вычисляют значения:
```go
total := 7 + 3
difference := 7 - 3
product := 7 * 3
quotient := 7 / 3
remainder := 7 % 3
```

Если оба операнда имеют целочисленный тип, деление выполняется как целочисленное: 7 / 3 равно 2. Оператор остатка возвращает 1 для 7 % 3.

Операторы сравнения возвращают bool:
```go
status >= 200
status < 300
status == 429
status != 404
```

Логические операторы объединяют булевы выражения:

| Оператор | Значение |
| --- | --- |
| && | оба выражения должны быть истинными |
| логическое OR | истинным должно быть хотя бы одно выражение |
| ! | меняет true на false и наоборот |

В isSuccessStatus нужны обе границы. Ответ со статусом 200 успешен, а 300 уже нет:

```go
return status >= 200 && status < 300
```

Go вычисляет && и || слева направо и останавливается, когда результат уже известен. Это называется коротким вычислением. Учитывайте порядок, если второе выражение зависит от первого.

## Условия и ранний возврат

if выполняет тело только при истинном условии:
```go
if attempt <= 0 {
    return 0
}
```

В примере для некорректного номера попытки выполняется ранний возврат. Благодаря этому основная часть расчёта не обёрнута в дополнительный else.

В if можно объявить переменную в необязательном инициализаторе. Её область видимости заканчивается вместе с этим оператором if:
```go
if success := isSuccessStatus(status); success {
    return "success"
}
```

Переменная success существует только внутри этого if и недоступна после закрывающей скобки. Маленькая область видимости уменьшает риск случайно использовать временное значение в другой ветке.

else if подходит для взаимоисключающих веток:
```go
if status >= 500 {
    return "server error"
} else if status >= 400 {
    return "client error"
} else {
    return "other"
}
```

После безусловного return обычно не нужен else, если только он не делает короткий учебный пример понятнее. В прикладном коде guard clauses часто читаются проще.

## Циклы через for

В Go есть одно ключевое слово для циклов — for.

Форма из трёх частей похожа на традиционный цикл for:
```go
for i := 1; i < attempt; i++ {
    delay *= 2
}
```

Здесь есть инициализатор (i := 1), условие (i < attempt) и пост-выражение (i++). Переменная i доступна только внутри цикла.

Цикл в retryDelaySeconds удваивает задержку для каждой повторной попытки после первой:

| Попытка | Задержка |
| ---: | ---: |
| 1 | 1 секунда |
| 2 | 2 секунды |
| 3 | 4 секунды |
| 4 | 8 секунд |

Есть и цикл только с условием:
```go
for condition {
    // повторяемая работа
}
```

break останавливает цикл, а continue пропускает остаток текущей итерации. С массивами, срезами и картами мы применим их в следующем уроке.

## Область видимости и затенение

Область видимости — часть программы, где доступно имя. Параметр функции доступен внутри функции. Переменная, объявленная в if или for, доступна только в этом блоке.
```go
func example(value int) int {
    if value > 0 {
        result := value * 2
        return result
    }

    // result здесь не существует.
    return 0
}
```

Будьте внимательны с :=: оператор объявляет новую переменную, если слева есть хотя бы одно новое имя в текущей области видимости. Случайное создание новой переменной вместо изменения внешней называется затенением. Компилятор обнаруживает некоторые неиспользуемые переменные, но не каждую ошибку затенения.

Предпочитайте короткие области видимости и имена, описывающие локальное назначение. Позже это пригодится в обработчиках, которые проверяют запросы и возвращают ошибки.

## Разбор примера

requestDecision разделяет три результата:

1. Ответ 2xx успешен.
2. Ответы 408, 429 и 5xx можно повторить.
3. Другие ответы должны остановить операцию.

retryDelaySeconds использует цикл вместо таблицы с жёстко заданными значениями. Это небольшой пример превращения повторяющегося правила в код. В реальном сервисе также нужны максимальная задержка, jitter и ожидание с поддержкой отмены; эти темы появятся позже в разделах про backend и надёжность.

## Как читать тесты

Тесты используют таблицу случаев. Каждый случай задаёт вход и ожидаемый результат. Граничные значения вроде 200, 299, 500 и 599 важны, потому что ошибки в условиях диапазонов часто возникают именно на границах.

Запустите тесты подробно:
```sh
go test -v ./lessons/02-control-flow
```

Перед коммитом запускайте все проверки репозитория:
```sh
go fmt ./...
go test ./...
go test -race ./...
go vet ./...
```

## Типичные ошибки

| Ошибка | Почему неверно | Как исправить |
| --- | --- | --- |
| Написать status >= 200 OR status < 300 | Почти любое целое удовлетворяет одной части такого условия | Для диапазона с двумя границами использовать && |
| Забыть про целочисленное деление | 7 / 3 даёт 2, а не дробь | Привести операнд к float64, если нужна дробь |
| Неправильно начать цикл | Можно пропустить первую попытку или добавить лишнюю задержку | Сначала выписать ожидаемые значения для попыток 1, 2 и 3 |
| Использовать переменную за пределами блока | Имя из if или for имеет ограниченную область видимости | Вынести объявление наружу только если значение действительно нужно дальше |
| Повторять любой ответ | Постоянные ошибки вроде 404 или 403 нельзя бездумно повторять | Задать явную политику повторов |

## Практика

1. Добавьте isValidPort(port int) bool. Возвращайте true только для портов от 1 до 65535. Проверьте обе границы и недопустимые значения.
2. Добавьте clamp(value, minimum, maximum int) int. Возвращайте ближайшую границу, если value выходит за диапазон. Зафиксируйте в документации предположение minimum <= maximum.
3. Добавьте isEven(value int) bool, используя оператор остатка. В тестах добавьте отрицательное чётное число.
4. Добавьте countDown(start int) []int, возвращающую значения от start до 0. Не записывайте каждое значение вручную — используйте цикл. Тип возвращаемого среза является предварительным знаком следующего урока.
5. В комментарии объясните область видимости success в requestDecision и почему переменную нельзя использовать после первого блока if.

Для каждой новой функции сначала напишите тесты, затем меняйте main. Добавляйте обычные значения, границы и хотя бы один некорректный или пустой случай, если это допускает контракт.
